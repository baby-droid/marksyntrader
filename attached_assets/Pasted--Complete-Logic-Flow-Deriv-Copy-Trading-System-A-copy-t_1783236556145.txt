## Complete Logic Flow: Deriv Copy Trading System

A copy trading system has two main components:

1. **Master Account** (the account whose trades are copied)
2. **Follower Account** (the account that copies the master's trades)

The overall flow looks like this:

```text
                  MASTER ACCOUNT
                 (API TOKEN LOGIN)
                        │

                        │
                        ▼

                        │
                        ▼

                        │
      ┌─────────────────┴─────────────────┐
      ▼                                   ▼
 Contract Bought                  Contract Closed
      │                                   │
      └──────────────┬────────────────────┘
                     ▼
             Trade Information
                     │
                     ▼
          Copy Trading Engine
                     │

      ▼                             ▼

      │                             │

      ▼                             ▼
 Monitor Position          Monitor Position
      │                             │
      ▼                             ▼
Close When Master Closes   Close When Master Closes
```

## Additional components to make the system robust

A production-quality copy trading system typically includes:

* **Connection Manager:** Maintains persistent WebSocket connections and automatically reconnects if disconnected.
* **Authentication Manager:** Validates API tokens, checks permissions, and refreshes session state after reconnects.
* **Trade Listener:** Subscribes to the master's trade updates and converts them into internal trade events.
* **Copy Engine:** Receives trade events, validates copy rules, and submits corresponding trades for followers.
* **Risk Manager:** Enforces limits such as maximum stake, daily loss, maximum concurrent trades, and account balance checks.
* **Stake Manager:** Calculates follower stake using fixed, proportional, percentage, or custom formulas.
* **Execution Manager:** Sends proposals and buy requests, handles API responses, retries when appropriate, and records execution results.
* **Position Monitor:** Tracks open contracts, updates profit/loss, and synchronizes follower state with the master's lifecycle where applicable.
* **Logging & Analytics:** Records every authorization, trade, error, execution latency, win/loss, and account statistic for monitoring and debugging.

This modular design makes it easier to test, maintain, and extend the system while keeping the trading logic separate from connection handling and risk management.
