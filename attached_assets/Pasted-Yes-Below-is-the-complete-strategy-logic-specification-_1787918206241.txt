# 1. EVEN / ODD

## A. ODD — primary strategy

### Distribution conditions

Analyze the last **1,000 ticks**, then compare 100, 50 and 20 tick windows.

For an ODD signal:

1. Find the 5 odd digits:

   * 1
   * 3
   * 5
   * 7
   * 9

2. Prefer when **3–5 odd digits are ≥ 10.5%**.

3. At the same time, look for weak even digits:

   * ideally several below **10–10.4%**.

4. Calculate total parity:

```text
ODD = frequency(1,3,5,7,9)
EVEN = frequency(0,2,4,6,8)
```

5. Stronger condition:

```text
ODD >= 55%
```

6. Stronger still if Odd is **increasing** across the windows.

### Example

```text
1 = 11.2%
3 = 10.8%
5 = 11.0%
7 = 10.7%
9 = 11.1%

Odd total = 55.0%

0 = 9.5%
2 = 9.4%
4 = 9.8%
6 = 9.7%
8 = 10.1%
```

This qualifies as an **ODD candidate**.

### Entry selection

Among the weak even digits, identify:

* lowest even %
* highest even %
* most recently appearing even digit

Then observe what happens immediately afterward.

Your intended entry concept is:

```text
weak even distribution
+
odd dominance
+
1–2 even occurrences
+
odd continuation
```

# 2. EVEN

EVEN is the mirror of ODD.

### Conditions

Find:

```text
0,2,4,6,8
```

Prefer:

```text
3–5 even digits >= 10.5%
```

while odd digits are weak.

Then:

```text
EVEN >= 55%
```

and preferably increasing.

### Example

```text
0 = 11.0%
2 = 10.8%
4 = 11.2%
6 = 10.7%
8 = 11.1%

EVEN = 54.8%
```

If the short windows show:

```text
20T = 57%
50T = 56%
100T = 55%
```

the Even side has stronger confirmation.

### Entry

Use the:

* lowest odd %
* highest odd %
* recent odd digit
* sequence pattern

to determine the entry.

# 23. MARTINGALE / RECOVERY

Your concept is **recovery-based**, not simply “double every loss.”

Example:

```text
Profit before loss = $10
Loss = $3
```

Remaining profit:

```text
$7
```

The next recovery trade should only target recovery of the relevant deficit, subject to the configured stake/risk ceiling.

If the loss grows:

```text
LOSS
LOSS
LOSS
```

the recovery requirement increases, but the system should eventually **stop recovery** rather than create an unlimited martingale sequence.

# 29. The unified decision engine

Ultimately, **every contract uses the same five-stage architecture**, while each contract has a different signal model:

```text
STAGE 1
DATA
1000 / 100 / 50 / 20 ticks
        ↓
STAGE 2
STRATEGY ANALYSIS
Even/Odd/Match/Diff/Over/Under/
Rise/Fall/Only Up/Only Down/
High/Low
        ↓
STAGE 3
PATTERN + DISTRIBUTION
        ↓
STAGE 4
VIRTUAL VALIDATION
        ↓
STAGE 5
RISK + EXECUTION
```

The most important implementation detail is that **the 1,000-tick distribution should be the baseline, while 100/50/20 ticks determine current entry timing**. That prevents the bot from treating a short sequence as meaningful without checking whether it is supported by the broader distribution.
