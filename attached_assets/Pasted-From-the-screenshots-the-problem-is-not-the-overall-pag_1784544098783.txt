From the screenshots, the problem is not the overall page width—it is the **vertical layout** of the right trading panel. At 100% browser zoom, the controls exceed the viewport height, so the action buttons ("Over" and "Under") are pushed below the fold. When you zoom to 67%, everything becomes visible because the browser is scaling the entire UI, not because the layout is better.

A better solution is to redesign the panel so it fits within a 1920×1080 display at 100% zoom.

# Recommended Right Panel

Target width:

```
340px–360px
```

Maximum height:

```
100vh
```

Use:

```
display:flex;
flex-direction:column;
overflow:hidden;
```

instead of allowing the panel to grow indefinitely.

# Responsive Scaling

Avoid relying on browser zoom. Instead, use CSS with viewport-based sizing:

```css
html {
    font-size: clamp(14px, 0.9vw, 16px);
}

.right-panel {
    width: min(360px, 24vw);
    height: 100vh;
}

.trade-button {
    min-height: 58px;
}

.digit-circle {
    width: clamp(56px, 3.2vw, 64px);
    height: clamp(56px, 3.2vw, 64px);
}
```

This lets the interface adapt between 1366×768, 1600×900, and 1920×1080 without needing browser zoom.

## Recommended Design Summary

* Right panel width: **350–360 px**
* Right panel height: **100vh** with no overflow
* Vertical spacing between sections: **10–12 px**
* Digit circles: **60–64 px** diameter
* Space between circles: **16–18 px**
* Trade buttons: **58–60 px** high
* Stake buttons: **40×40 px**
* Use brighter accent colors: Green **#00E676**, Red **#FF3D57**, Yellow **#FFD600**, Blue **#1E88FF**
* Add subtle glow and tinted backgrounds for active selections
* Use responsive CSS (`clamp()`, `vw`, `vh`) instead of depending on browser zoom so that all controls remain visible at 100% zoom on standard desktop resolutions.
