# MARK SYN TRADER — TRADE SIGNAL LOGIC ONLY

The signal engine should treat **market selection, contract selection, barrier/digit selection, and entry timing as separate decisions**. No trade is generated unless the required conditions align.

## 1. Universal market-analysis engine

For every market, continuously maintain:

```text
1000 ticks → regime/baseline
100 ticks  → current structure
50 ticks   → momentum
20 ticks   → confirmation
10 ticks   → entry timing
```

For each window calculate:

```text
• digit distribution 0–9
• even/odd distribution
• rise/fall ratio
• consecutive runs
• reversals
• repetition
• gaps
• momentum
• volatility
• entropy/dispersion
• pattern recurrence
• recent-vs-baseline change
```

### Universal signal condition

```text
1000 = LONG-TERM CONTEXT
100  = STRUCTURE
50   = MOMENTUM
20   = CONFIRMATION
10   = ENTRY TRIGGER
```

If the windows materially disagree:

```text
NO TRADE
```

If they converge:

```text
SETUP → CONFIRM → ENTRY NOW
```

# 19. RUN LOGIC

The signal should return:

```text
RUNS = 1–10
```

based on signal persistence and quality.

Example:

```text
65–69 → 1 run
70–74 → 2 runs
75–79 → 3 runs
80–84 → 4 runs
85–89 → 5 runs
90+   → maximum configured runs
```

But every run must be **revalidated**.

```text
RUN 1
↓
RESCAN
↓
still valid?
↓
RUN 2
```

Never:

```text
RUN 1 LOSS
↓
automatically double
↓
RUN 2
```

unless the user explicitly enables a bounded recovery strategy.
